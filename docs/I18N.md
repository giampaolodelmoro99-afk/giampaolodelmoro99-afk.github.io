# Internazionalizzazione

## 1. Lingue

- **Italiano** (`it`): lingua di default, URL senza prefisso.
- **Inglese** (`en`): URL con prefisso `/en/`.

Decisione e alternative in ADR-0008 (dizionari tipizzati invece di react-i18next).

## 2. URL per lingua (slug tradotti)

La mappa sta in `src/routes/routeMap.ts`:

```ts
export const routeMap = {
  desktop: { it: "/", en: "/en/" },
  // esempio futuro: projects: { it: "/progetti/", en: "/en/projects/" },
} as const satisfies Record<string, Record<Locale, string>>;
```

- Gli slug sono tradotti nella lingua della pagina, in kebab-case, senza accenti.
- La forma canonica ha la slash finale (tranne `/`), coerente con il 301 di GitHub Pages.
- `localeFromPathname()` ricava la lingua dal percorso: è l'unica fonte della lingua attiva.
- `routeKeyFromPathname()` trova la chiave della route, utile per passare alla stessa finestra nell'altra lingua.

## 3. Dizionari

```
src/i18n/
  it.ts      export const it = {...}; export type Dictionary = typeof it;
  en.ts      export const en: Dictionary = {...}
  index.ts   getDictionary(locale), useLocale(), useT()
```

- `en` è tipizzato come `Dictionary`: una chiave mancante o in più è un errore di compilazione.
- Chiavi in inglese, raggruppate per area (`meta`, `person`, `desktop`, `notFound`…). Dalla Fase 2 ogni app lazy avrà i propri dizionari accanto al codice (`features/<app>/i18n/it.ts`, `en.ts`), così i testi non pesano sul chunk iniziale.
- I testi includono `alt`, `aria-label`, titoli delle finestre e messaggi di errore.
- I componenti usano `useT()`; i moduli non React (meta, JSON-LD) usano `getDictionary(locale)`.

## 4. hreflang e x-default

Ogni pagina dichiara:

- `<html lang="it|en">`
- `link rel="alternate" hreflang` per ogni lingua che ha la stessa route
- `hreflang="x-default"` verso la versione italiana
- `og:locale` e `og:locale:alternate` (`it_IT`, `en_US`)

La sitemap (F5) riporta gli stessi alternate.

## 5. Cambio lingua

- Il selettore della lingua è un `Link` di React Router verso la **stessa finestra** nell'altra lingua (`routeMap[key][altraLingua]`), con `hrefLang` e `lang`.
- Nessun ricaricamento di pagina. `lang` del documento, titolo e meta si aggiornano con la navigazione.
- Le pagine non tradotte non esistono: ogni route ha entrambe le lingue.

## 6. Persistenza

La preferenza di lingua può essere salvata in localStorage (chiave `locale`, F4A, dal Pannello di controllo). **L'URL vince sempre**: la preferenza serve solo a scegliere dove andare da azioni senza URL (es. "Esegui…"). Nessun redirect automatico in base alla lingua del browser, per non confondere i crawler.

## 7. Formati

- Date: `Intl.DateTimeFormat(locale, …)`. Numeri: `Intl.NumberFormat`. Plurali: `Intl.PluralRules`.
- Ogni valore mostrato ha etichetta e unità, tradotte.
- Nessuna libreria di formattazione esterna.

## Testi dei componenti (Fase 1B)

I componenti di `src/components/` non conoscono la route: leggono i loro testi da `src/i18n/ui.ts` (es. `progressBar.inProgress`, `window.close`) con `useUiStrings()`, che sceglie la lingua dall'`I18nProvider` di React Aria. Storybook lo imposta dal comando Lingua; nel sito lo farà il root dalla F2A, con `intlLocales` di `routeMap.ts`. Una lingua non prevista ricade sull'italiano.

I testi dei componenti stanno in un dizionario separato da `it.ts`/`en.ts` perché quelli entrano nel JS iniziale della home: con i componenti dentro, la home cresceva di 0,2 kB senza usarli (misura del 18/10/2026).
